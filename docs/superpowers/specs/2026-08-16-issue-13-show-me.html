Issue #13 · diseño productivo

doctor mira, valida y reporta.

La primera CLI de tbboot inspecciona un Consumer repository y sus Sources locales. No instala, no corrige drift y no deja estado detrás.

tbboot doctor [--root <consumer-root>] [--json]
1EntradaArgumentos y raíz absoluta del Consumer repository.
2ContratoLee y valida tbboot.yaml antes de resolver.
3DescubrimientoSolo provider local; Source y Recipes de primer nivel.
4PreflightRutas seguras, orden de Steps, colisiones y Artifacts.
5ResultadoUn envelope, salida humana o JSON, y exit code.

Frontera de seguridad

LeeManifest, source.yaml, recipe.yaml, inputs del Source y targets del Consumer.
Nunca escribeArtifacts, lockfile, .tbboot, trust store, cachés o metadatos. Tampoco ejecuta Git.

Resolución de rutas

input  = relativo a Recipe → dentro de Source
target = relativo a raíz del Consumer repository

realpath + symlinks
  ├─ escape de Source   → conflict
  └─ escape de Consumer → conflict

La comprobación produce estados, no cambios

File

satisfied bytes idénticos
missing target ausente
drift existe, pero difiere
conflict input ausente, escape o colisión

Un File no puede compartir target con ningún otro escritor.

File Fragment

satisfied bloque completo e idéntico
missing target o bloque ausente
drift bloque existente diferente
conflict markers duplicados, incompletos o incompatibles

Varios fragments pueden compartir target si sus markers son distintos.

El envelope común

{
  "schemaVersion": 1,
  "command": "doctor",
  "status": "ok",
  "changed": false,
  "actions": [],
  "diagnostics": []
}

Cómo termina

  • ok / 0todos los Steps satisfechos
  • warning / 0falla solo un Step optional
  • error / ≠0falla un Step requerido o hay conflicto
  • stderrlogs auxiliares; en --json, stdout es un único JSON

Forma mental del flujo

for each manifest source:
  reject provider != local
  source = read + validate(source.yaml)
  for each first-level recipe in deterministic order:
    recipe = read + validate(recipe.yaml)
    for each ordered step:
      resolve input + target safely
      detect File / File Fragment state
      append action + diagnostic
aggregate severity → serialize once → exit

Fuera de esta slice: Git, Source dependencies, Custom, uninstall, Catalogs y selección efectiva de Recipes. La implementación prevista cabe en src/cli.ts, src/contract.ts y src/doctor.ts.
