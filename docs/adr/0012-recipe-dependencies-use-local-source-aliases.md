# Recipe dependencies use local Source aliases

The future contract allows a Manifest or Source dependency to select Recipes explicitly by relative path. A Source declares each dependency with the same structured provider, locator, selector, and `recipes` fields as a Manifest Source entry, plus a local `name` alias. A Recipe refers to a selected dependency Recipe through that alias using the canonical `requires` field; `doctor` validates prerequisites first, `install` processes them before the dependent Recipe, and `uninstall` reverses the effective install order. When Recipe dependencies are implemented, each declared dependency is mandatory; optionality applies to Steps only. For both Manifest and Source dependencies, an omitted `recipes` field means all Recipes, a non-empty list selects only those Recipes, and an empty list is invalid. The alias is local and is not a global Source or Recipe ID. Recipes do not install Sources directly. The MVP reserves these fields but rejects non-empty Recipe selections or Recipe dependency declarations before writing.
